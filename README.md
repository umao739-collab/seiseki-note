# せいせきノート

青葉出版「SMILEスプレッドシート」の成績をもとに、次の4つを作る Google Apps Script の Web アプリです。

| 機能 | できること |
|---|---|
| 📄 個票 | 一人ずつ、教科・観点ごとの到達率、単元ごとの A/B/C、「とくい」「のびしろ」「のびたところ」を1枚にまとめます。1人分でも全員分でも印刷でき、PDFにもできます |
| 📊 クラスの傾向 | 単元ごとの平均と A・B・C の人数、つまずきやすかった単元、次の授業のヒント、気にかけたい子、全員×単元の一覧表を出します |
| ✏️ 所見づくり | テストの結果から所見の下書きを作ります。「短め・ふつう・長め」の長さ、「別の言い方」、全員分の一括作成ができ、SMILEファイルに保存します。名前と点数を入れない「AIに頼む文」もコピーできます |
| 🔍 入れわすれ | 何人かは点数が入っているのに、空いている子がいる単元を見つけます |

SMILEファイルの中身は書きかえません。所見を保存するときだけ、「所見メモ（せいせきノート）」シートをファイルに足します。

## 安全のしくみ（ふりかえりシート 他校版と同じ考え方）

| 考え方 | ふりかえりシート 他校版 | せいせきノート |
|---|---|---|
| 本人の決め方 | `getMe_` が `Session.getActiveUser()` だけを見る。画面から来たメールは見ない | 同じ（`Auth.gs`） |
| 拒否が既定 | 名簿にない人・学校が休止中なら断る | 学校のドメイン（`ALLOWED_DOMAINS`）以外は、ファイルを開く前に断る |
| 公開関数 | 末尾 `_` の無い関数は `PUBLIC_FUNCTIONS` だけ。テストで照らし合わせる | 同じ（9個）。全部が `guard_` → `getMe_` の順で始まることもテストで確かめる |
| 例外 | `appError_` の文言だけを画面に返す。ほかは固定の文言にする | 同じ。ログには例外の種類と場所だけを残し、中身（名前・点数）は残さない |
| シートへの書きこみ | `escapeFormula_` を通し、テキスト書式（@）にして `setValues` で書く | 同じ（所見メモ） |
| 画面 | `innerHTML` を使わず、文字は文字として出す | 同じ。DOM を作る小さな関数（`h()`）で、`textContent` だけを使う |
| データの置き場所 | アプリ管理者のマスタと年度データにまとめる（`USER_DEPLOYING`） | **まとめない**。開いた先生の権限で動き（`USER_ACCESSING`）、その先生のSMILEファイルを読むだけ |

成績はとても大事な個人情報です。そのため、ふりかえりシートとちがって「アプリ管理者のところに集めない」作りにしました。

- 成績を、マスタ・キャッシュ・ログ・外部のサービスに写しません（`UrlFetchApp`・`CacheService`・`console.log` を使っていないことを、テストで確かめます）。
- 分析と所見づくりは、先生のブラウザの中だけで行います。サーバーに送るのは、保存する所見の文と設定だけです。
- 先生ごとの設定（えらんだファイル・表示の好み）は、その先生の `UserProperties` に置きます。
- どのファイルを読むかは、サーバーが本人の `UserProperties` から決めます。画面からファイル ID を受け取るのは「えらぶ」ときだけで、そのときも SMILE ファイルかどうか（メニューシートの B1）を確かめます。
- 個票の印刷には「気にかけたい子」などの先生用の情報を入れません。
- 「AIに頼む文」には、名前・番号・点数・％を入れません（「学級の中では高め」のような言葉だけ）。これもテストで確かめます。

## 初期設定（アプリを用意する人が1回だけ）

ふりかえりシートと同じく、Apps Script のプロジェクトを1つ作って、Web アプリとして公開します。先生方は URL を開くだけです。

1. https://script.google.com で「新しいプロジェクト」を作り、名前を「せいせきノート」にします。
2. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」にチェックを入れます。
3. `src/` の中のファイルを、同じ名前でエディタに作ってはりつけます（`.gs` はスクリプト、`.html` は HTML。`index.html` は `index` という名前にします）。
   - `appsscript.json`・`Config.gs`・`Auth.gs`・`Rules.gs`・`SmileReader.gs`・`Code.gs`・`Demo.gs`
   - `index`・`Styles`・`Logic`・`App`
4. 他校に配るときは、`Config.gs` の `ALLOWED_DOMAINS` だけを、その学校のドメインに書きかえます（奈良市は `e-net.nara.jp`）。
5. 「デプロイ」→「新しいデプロイ」→ 種類は「ウェブアプリ」にします。
   - 次のユーザーとして実行: **ウェブアプリケーションにアクセスしているユーザー**
   - アクセスできるユーザー: **（学校のドメイン）内の全員**
6. 出てきた URL を先生方に配ります。

> `appsscript.json` に同じ設定が書いてあるので、デプロイの画面ではそれを確かめるだけです。

## 先生の使い方

1. URL を開きます。初めてのときは、Google の「アクセスを許可」の画面が出るので「許可」を押します（1回だけです）。
2. 「あなたのSMILEファイル」の一覧から、自分のクラスのファイルを押します。一覧にないときは、URL をはりつけます。
3. 自動で読みこまれます。あとはタブを切りかえるだけです。

まずはファイルをえらばずに「🧸 見本のクラスをひらく」で試せます。見本の名前と点数はすべて作りものです。

## SMILEファイルの読み方

セルの位置は決め打ちせず、見出しの文字を探して読みます。

- メニューシート: B1 の「SMILE」で SMILE ファイルかどうかを見分けます。学年（F1）・組（H1）・先生名（H2）・学期制（E1）を読み、「№」「名前」の見出しの下を名簿として読みます（校務連携CDは読みません）。
- 教科シート（国語・社会・算数・理科・生活・音楽・図工・家庭・体育・外国語のうち、ファイルにあるもの）:
  - 「単元名／観点」の行に単元名があり、その下が観点、その下が配点、さらに「学級平均」の行の次から児童の行です。
  - 観点の列は「単元合計」の列の手前までです。配点が空の観点は、その単元では使っていないものとして読みません。
  - 時期は、上にある「【1学期】」などの見出しから読みます。A・B の基準は「A=」「B=」の右の数を読みます。
  - 右側の「得点集計表」（2つめの「単元名／観点」から右）は読みません。
  - 単元の評価は、SMILE の「単元評価」の列に A/B/C があればそれを使います。なければ A・B の基準から計算します。

## 試し方（開発する人向け）

```bash
node seiseki-note/tools/run-local-tests.js
```

安全のきまり・入力の検査・SMILE の読み取り・分析・所見を確かめます（Node.js だけで動きます）。

```bash
node seiseki-note/tools/build-preview.js
```

`preview/index.html` を作ります。GAS を使わずに、ブラウザで画面（見本のクラス）を確かめられます。`?file=1` を付けて開くと、「自分のファイル」のときの動き（保存など）も試せます。

## まだ確かめていないこと

- 本物の Apps Script での実行はまだです（Node のテストと、ブラウザの見本の画面で確かめました）。
